# M3 resume after reload: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a multipart upload interrupted by a reload continues when the user picks the same file again: the client asks
`/complete` which parts the bucket lacks and sends only those; it is on by default, scoped by namespace, and forgotten on
sign-out.

**Architecture:** four new client modules (`records.ts` the IndexedDB store, `fingerprint.ts` the file match,
`locks.ts` the Web Lock, `resume.ts` the three public calls) and small hooks in the existing run (`job-run.ts`,
`file-run.ts`, `upload.ts`, `retry-file.ts`, `lifecycle.ts`): save once per multipart ticket, delete when the file ends,
start a resumed file at `/complete`. Platform fakes for IndexedDB and Web Locks in `src/testing/`.

**Tech Stack:** TypeScript 7, web-platform APIs only (IndexedDB, Web Locks, `crypto.subtle`), Vitest 5 with fake timers,
the fake R2 and fake XHR, Playwright on RustFS and live R2, the Next.js lab.

**Spec:** [`docs/superpowers/specs/2026-11-16-resume-design.md`](../specs/2026-11-16-resume-design.md) (owner-approved
2026-11-16; binding). Parent: design spec §6.3 (amended by the resume design §8). Current client: plans A and B,
decisions `M3-U1`..`M3-U59` in `docs/decisions/m3-uploader.md`.

## Rulings fixed by this plan (recorded as `M3-U60`… in Task 7)

- **R1. Store shape:** database `cloudrop`, version 1, object store `uploads` with `keyPath: "id"`, no index (a
  namespace's records are read with `getAll()` and filtered: at most a few hundred records, each a few KiB).
- **R2. One ordered queue per client:** every store operation is chained on one promise, so a `remove` issued after a
  `save` runs after it (spec §3.2). The database is opened once, lazily, on the first operation; a failed open makes
  every later operation fail the same way (uploads ignore it; `resumable`/`forget` report `STORAGE_ERROR`).
- **R3. Expiry margin:** a record whose `expiresAt` is less than 60 000 ms ahead counts as expired (spec §3.6).
- **R4. Lock name** `cloudrop:upload:<id>`, requested with `ifAvailable: true` and held until the file's run settles
  (done, failed or aborted). A retry of a failed file asks again. Without `navigator.locks` nothing is locked.
- **R5. The resumed file's first run treats `UPLOAD_EXPIRED`, `INVALID_TOKEN` and `NO_SUCH_UPLOAD` from its probe as
  "start over"** within the same run: it does not settle, asks `/upload` for a new ticket and sends the whole file; its
  first outcome (`M3-U35`) is the outcome of that run. `retry()`'s new-ticket list gains `NO_SUCH_UPLOAD`.
- **R6. The probe's first `PARTS_MISSING` is free:** it consumes none of `REPAIR_ROUNDS`; a later one counts as usual.
  After it, the parts not named missing count their full size in `bytes` (the snapshot's bytes before it are 0).
- **R7. `resume()` validates in this order:** arguments → record exists in the namespace and is not expired → file
  match (§3.3) → lock. The first failure ends the job with `{ data: null, error }` and sends nothing.
- **R8. `ResumableUpload` fields** are exactly `{ id, route, name, size, type, lastModified, expiresAt }`; the token,
  key and metadata never leave the store through the public API.
- **R9. `forget()` options:** `forget()` deletes the client's namespace; `forget({ all: true })` deletes every record.
  Any other argument is `INVALID_INPUT`.
- **R10. Options:** `persist` must be a boolean (default `true`), `namespace` a string of at most 256 characters
  (default `""`); anything else is `configError` with a message naming the option.

### Task 1: The record store and a fake IndexedDB

**Files:** create `packages/cloudrop/src/client/records.ts`, `records.test.ts`, `packages/cloudrop/src/testing/fake-indexeddb.ts`.

**Interfaces:**
```ts
// client/records.ts
export interface UploadRecord {
  id: string; namespace: string; route: string; metadata: unknown;
  name: string; size: number; type: string; lastModified: number; fingerprint: string;
  token: string; key: string; partSize: number; partCount: number; expiresAt: string; savedAt: number;
}
export interface Records {
  /** Queued; never rejects; a failure is dropped (an upload never waits for or fails on the store). */
  save(record: UploadRecord): void;
  remove(id: string): void;
  /** The namespace's record with this id, or null (also when it expired: then it is removed). */
  get(id: string, namespace: string): Promise<Result<UploadRecord | null>>;
  /** The namespace's unexpired records, newest first (`savedAt` descending); expired ones are removed. */
  list(namespace: string): Promise<Result<UploadRecord[]>>;
  /** Deletes the namespace's records, or every record when `namespace` is null; resolves the count. */
  clear(namespace: string | null): Promise<Result<number>>;
}
/** A store over globalThis.indexedDB; a no-op one (lists [], counts 0) when `enabled` is false or there is none. */
export function createRecords(enabled: boolean, now?: () => number): Records;
// testing/fake-indexeddb.ts
export interface FakeIndexedDb {
  indexedDB: unknown;                               // for vi.stubGlobal("indexedDB", …)
  /** The records stored, by id, as a structured clone would keep them. */
  stored(): Record<string, unknown>;
  /** Makes the next n requests (open or any store request) fail with this DOMException name. */
  failNext(name: "QuotaExceededError" | "UnknownError" | "InvalidStateError", n?: number): void;
}
export function fakeIndexedDb(): FakeIndexedDb;
```

- [ ] **Step 1: the fake.** Implement exactly the subset `records.ts` uses: `indexedDB.open(name, version)` returning a
  request with `onupgradeneeded` (its `result.createObjectStore(name, { keyPath })`), `onsuccess`, `onerror`;
  `db.transaction(storeName, mode)` with `objectStore(name)`, `oncomplete`, `onerror`, `onabort`; store `put`, `get`,
  `getAll`, `delete`; requests with `result`, `error`, `onsuccess`, `onerror`. Events fire asynchronously (a
  microtask or `setTimeout(0)`), values are structured-cloned (`structuredClone`) on write and read, and a transaction
  completes after its requests. Header comment: what it fakes, never shipped.
- [ ] **Step 2: failing tests** (`records.test.ts`, `vi.stubGlobal("indexedDB", fake.indexedDB)`, injected `now`):
  1. `save` then `list(ns)` returns the record with every field equal to the literal saved (structured clone, not the
     same object).
  2. Namespaces never mix: records of `"a"` and `"b"`; `list("a")` has only `"a"`'s; `clear("a")` resolves 1 and leaves
     `"b"`'s; `clear(null)` deletes the rest and resolves its count.
  3. Newest first by `savedAt`.
  4. Expiry with the 60 s margin (R3): `expiresAt` = now + 59 999 ms is expired and removed by `list`; now + 60 000 ms
     is listed. `get` of an expired record resolves null and removes it.
  5. Order (R2): `save(r)` then `remove(r.id)` issued synchronously → nothing stored; `remove` then `save` → stored.
  6. A failing `put` (`failNext("QuotaExceededError")`): `save` does not throw or reject; a later `list` still works.
  7. A failing open: `list` and `clear` resolve `{ data: null, error }` with code `STORAGE_ERROR` and a message that
     names the browser's storage and contains neither the DOMException name nor its text; `save` is silent.
  8. No `indexedDB` global, and `createRecords(false)`: `list` → `ok([])`, `get` → `ok(null)`, `clear` → `ok(0)`;
     `save`/`remove` do nothing; no global is touched.
  9. The database is opened once for many operations.
- [ ] **Step 3: implement** `records.ts` (one lazily opened database, one promise queue, `getAll` + filter, R1–R3).
- [ ] **Step 4:** `bun run verify`; report the client size (the module is not imported by the entry yet, so unchanged).
  **Commit** `feat(client): keep upload records in IndexedDB`.

- [ ] **Step 1: failing tests.**
  - `fingerprint.test.ts`: oracle = SHA-256 hex computed in the test with `node:crypto`'s `createHash` (a different
    implementation from WebCrypto) over the literal edge bytes:
    1. a 200 KiB file of `offsetBytes` → hash of bytes 0–65 535 then 139 264–204 799;
    2. exactly 128 KiB and 1 byte → whole file; 128 KiB + 1 → edges (boundary);
    3. a 0-byte file → hash of nothing;
    4. two files differing only in byte 65 535 differ; only in the last byte differ; only in a middle byte are equal
       (documents the heuristic);
    5. no `crypto.subtle` (stub `crypto` without `subtle`) → `""`;
    6. `isSameFile`: equal → true; each of name, size, lastModified, type and edge bytes changed alone → false.
  - `locks.test.ts`: taken and held until `until` settles (then `held()` is empty); another holder → false, and the
    callback never holds it; no `navigator.locks` → true; the name is `cloudrop:upload:<id>`.
- [ ] **Step 2: implement.** Messages (exact):
  - `uploadInUse`: `This upload is being sent in another tab of this browser. Finish or close it there, then try again.`
  - `notResumable`: `This upload can no longer be resumed: it finished, was cancelled or expired. Start it again.`
  - `notSameFile`: `This is not the file the upload started with. Pick the same file again to resume it.`
  - `storageUnavailable`: `The browser's storage for unfinished uploads could not be read or written. Uploads still work; resuming after a reload may not.`

### Task 5: `resumable()`, `resume()`, `forget()` and the probe

**Files:** create `client/resume.ts`, `client/resume.test.ts` (split if over 400 lines); modify `client.ts` (the three
methods, typed: `resumable<TName>(route?)`, `resume<TName>(upload: ResumableUpload<TName>, file, options?)`,
`forget(options?)`), `types.ts` (`ResumableUpload<TName = string>`), `upload.ts` (R6: the free first `PARTS_MISSING`
and the bytes after it), `job-run.ts`/`job.ts` (a job built from a record: its args from the record, its file's
`Upload` rebuilt with `parts: []` and every part landed, R5 in its first run).

- [ ] **Failing tests first** (oracles: the request log, the fake bucket's bytes, `fake.stored()`):
  1. `resumable()`: records of the namespace, newest first, exactly R8's fields; filtered by route; expired ones absent
     and removed; `ok([])` with `persist: false` and without `indexedDB`; `STORAGE_ERROR` when the store fails.
  2. A file interrupted after 2 of 4 parts (stop the first client by aborting its PUTs without `abort()`, as a reload
     would: drop the job; a new client on the same fake IndexedDB): `resume(record, sameFile)` sends
     `POST /complete`, then exactly `PUT part 3`, `PUT part 4`, `POST /complete`; the stored object equals the file;
     the record is removed; `done` is `{ data: { files: [done] }, error: null }`.
  3. Every part landed before the reload → `resume()` sends only `POST /complete` and ends done; a `/complete` that
     finished before the reload (the first client's `/complete` answered but dropped) → `POST /complete` only, done,
     same key.
  4. R6: the probe's `PARTS_MISSING` then two repair rounds that each lose a part still complete; the snapshot's
     `bytes` is 0 before the probe answers and the landed parts' sizes after.
  5. R5: the probe's `/complete` answered `UPLOAD_EXPIRED` (a fixture fault; the record itself is not yet expired by
     the client's clock), `INVALID_TOKEN`, `NO_SUCH_UPLOAD` → one new
     `POST /upload` with the record's route and metadata, the whole file, a new key, old record removed, new one saved,
     `done` reports done.
  6. R7 errors, each sending nothing: bad arguments; unknown id; another namespace's record; expired; a different file
     (each field and the edge bytes); lock held elsewhere → `UPLOAD_IN_USE`.
  7. A resumed job behaves as any job: pause and resume during the missing parts; `abort()` → `/abort` and record
     removed; a failure keeps the record and `retry()` probes again.
  8. `forget()` → count and nothing left of the namespace; `forget({ all: true })`; a bad argument → `INVALID_INPUT`;
     `forget()` while a file of the namespace is uploading leaves the upload running (it saves no new record unless it
     gets a new ticket).
  9. Types (`types.test.ts`): `resume()` returns `UploadJob<RouteResult<…>>` for the record's route; `resumable()`
     resolves `Result<ResumableUpload<RouteName>[]>`.
