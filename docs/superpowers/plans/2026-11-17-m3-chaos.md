# M3 chaos proxy: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a fault-injecting HTTP proxy between cloudrop's server and RustFS, a `test:chaos` Node lane, browser rows and
a nightly soak, proving every upload under faults ends with exact bytes and nothing left, or a clear error code.

**Architecture:** `src/testing/chaos-proxy.ts` (zero-dependency, `node:http`/`node:net`, test-only) forwards to RustFS
with the `Host` header untouched, so presigned URLs signed for the proxy stay valid; rules fault single requests
(presigned PUTs or the server's own S3 calls). A lane script runs RustFS in Docker behind it; scenario files use the
real `createCloudrop` + `s3()` and the real client.

**Tech Stack:** TypeScript 7, Node 24 `http`/`net`, Vitest 5, RustFS 1.0.5 in Docker (`scripts/rustfs.sh`), Playwright,
GitHub Actions.

**Spec:** [`docs/superpowers/specs/2026-11-17-chaos-design.md`](../specs/2026-11-17-chaos-design.md) (binding).
Research: `.superpowers/research/research-chaos.md`. Decisions: new series `M3-K` (`docs/decisions/m3-chaos.md`).

## Global Constraints

- Everything in English. `packages/cloudrop` keeps zero runtime dependencies; the proxy is test-only code under
  `src/testing/`, excluded from `tsconfig.json` (like `page-events.ts`) and typed through `tsconfig.test.json`.
- Source files 200–220 lines (check fails over 250; tests over 400; complexity over 15).
- Load `testing-patterns` before tests and `code-quality` before commits. Owner's rule: every edge case covered, zero
  AI-slop tests: independent oracles (SHA-256 of the stored object, the proxy's log of what reached the bucket,
  `ListMultipartUploads` empty), the failing case beside the happy one, fault probes for new branches.
- Lanes: `*.chaos.integration.test.ts` runs only through `bun run test:chaos` and **fails, never skips**, when Docker
  or RustFS is missing. Containers carry the label `cloudrop.test` and are removed at the end (trap registered first).
- The proxy log and every test output never hold a query string, a header value or a body (signatures; AGENTS.md).
- Never change the live bucket's settings. Live R2 is not used by this plan.
- Ports: the chaos lane's RustFS uses `CLOUDROP_RUSTFS_PORT` default 19300 (not 19000 or 19100); the proxy binds
  `127.0.0.1` on a free port. Port 5173 belongs to whichever task a wave names.
- Git: stage exact paths, conventional commits, never push; never `git stash`, `reset`, `clean`, `checkout --`. Never
  write outside the worktree you were given (no `/tmp`).
- Node 24: `PATH=~/.nvm/versions/node/v24.22.2/bin:$PATH`. `bun run verify` for every task.

## Proxy API (Task 1 produces; Tasks 4–7 consume)

```ts
// packages/cloudrop/src/testing/chaos-proxy.ts
export type ChaosOperation =
  | "PutObject" | "UploadPart" | "CreateMultipartUpload" | "CompleteMultipartUpload" | "AbortMultipartUpload"
  | "ListParts" | "HeadObject" | "GetObject" | "DeleteObject" | "ListObjectsV2" | "ListMultipartUploads" | "Options"
  | "Other";
export interface ChaosMatch {
  kind?: "presigned" | "server";       // presigned: X-Amz-Signature in the query; server: an Authorization header
  operation?: ChaosOperation;
  part?: number;                       // UploadPart's partNumber
  nth?: number | "every";              // 1-based among this rule's matches; default 1
}
export type ChaosFault =
  | { kind: "reset"; afterBytes: number }
  | { kind: "close" }
  | { kind: "blackhole" }
  | { kind: "delay"; ms: number; when: "before" | "after" }
  | { kind: "throttle"; bytesPerSecond: number }
  | { kind: "answer"; status: number; body?: string; headers?: Record<string, string>; cors?: boolean; exposeRetryAfter?: boolean }
  | { kind: "truncate" }
  | { kind: "stripCors" };
export interface ChaosRule { match: ChaosMatch; fault: ChaosFault }
export interface ChaosEntry {
  label: string;                       // "PUT part 2", "PUT object", "OPTIONS", or the server operation name
  kind: "presigned" | "server" | "preflight";
  fault: ChaosFault["kind"] | null;
  outcome: number | "reset" | "closed" | "held" | "error";
  bytesIn: number;
  startMs: number;
  endMs: number | null;
  inFlightAtStart: number;             // presigned PUTs in flight when this request started
}
export interface ChaosRandom { seed: number; resetRate: number; busyRate: number; latencyMs: [number, number] }
export interface ChaosProxy {
  readonly url: string;                // http://127.0.0.1:<port>
  set(rules: readonly ChaosRule[]): void;   // replaces the rules and their nth counters
  random(options: ChaosRandom | null): void;
  release(): void;                     // answers every black-holed request with a reset
  log(): readonly ChaosEntry[];
  clearLog(): void;
  stop(): Promise<void>;               // closes the server and every open socket
}
export function startChaosProxy(target: string, options?: { port?: number; control?: boolean }): Promise<ChaosProxy & { controlUrl?: string }>;
```

`control: true` adds a JSON control endpoint on a second loopback port (`POST /rules`, `POST /random`, `POST /release`,
`GET /log`, `POST /clear-log`) for the browser lane.

### Task 1: The proxy

- [ ] **Failing tests** (`chaos-proxy.test.ts`, unit lane, a local `node:http` echo target that records what reached it,
  no Docker): a request forwarded with its `Host` header untouched and its body intact; labels for each operation
  (PUT with `partNumber`, PUT without, `POST ?uploads`, `POST ?uploadId`, `GET ?uploadId`, `DELETE ?uploadId`, `HEAD`,
  `GET ?list-type=2`, `GET ?uploads`, `OPTIONS`); presigned vs server by query/header; `nth` (the second match faulted,
  the first and third forwarded) and `"every"`; `OPTIONS` never matches a PUT rule; reset after N bytes (the target
  got fewer than the body; the client sees `ECONNRESET`); close; black hole held until `release()` and until `stop()`;
  delay before/after (elapsed ≥ ms, fake-free real timers with small ms); throttle (elapsed ≥ size / rate);
  answer with and without CORS (`Access-Control-Allow-Origin` echoes the request's `Origin`; `Expose-Headers:
  Retry-After` only with the flag); truncate (headers arrive, the body does not; the target still got the request);
  strip CORS; the random mode is reproducible for one seed; `inFlightAtStart` counts concurrent presigned PUTs; the log
  holds no `?`, no `X-Amz` and no header value (assert over the serialized log); `stop()` leaves no open handle (the
  test process exits; check `server.listening === false`). Keep rows fast (each under 50 ms where possible; state the
  reason for any over 250 ms).
- [ ] **Implement**; add the file to `tsconfig.json`'s `exclude`; `bun run verify`. **Commit**
  `test: add a fault-injecting proxy for the chaos lanes`.
